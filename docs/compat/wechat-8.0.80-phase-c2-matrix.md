## 判定约定

- **PASS**：只用于本轮实际观察到该功能的 UI/业务效果；Hook 注册或候选定位不算 PASS。
- **PARTIAL**：只确认父功能的一项子功能，父功能整体仍未验收。
- **NOT_VERIFIED**：做过尝试但缺少目标 locator、安装代次/有效句柄、真实回调或闭环证据；不等于 FAIL。
- **NOT_TESTED**：本轮未尝试该项；不等于 FAIL。
- **NOT_ENABLED**：已知原始功能开关关闭，本轮未启用验证；不计入兼容 PASS。
- 全部 87 项都由主进程 `FeatureRegistry` 统一注册。`ModuleEntry` 还会在 AppBrand 进程以轻量路径独立安装 #55、#57–59；其余 AppBrand 进程没有完整功能注册表。未测试项的逐项定位/Hook 状态明确记为 NOT_VERIFIED，而不是从 `DexFinder.resolveAll()` 或注册句柄推断。
- `Feature` 默认全局开关为 `featureId + "_enabled"`、缺省 true，默认策略为 `PREINSTALL_HOOKS`；#12、#17 改用 `ENABLED_ONLY` 与自定义 enabled 检查，#02 强制启用，#86 使用自身设置作为 enabled predicate。功能自己的子设置、资源或场景仍可能关闭实际回调。
- 运行时缺少逐项目标类/方法、Hook handle、有效安装代次及缓存 hit/miss 遥测。本表不臆造这些状态。共享异常隔离及 cache 设计见报告 §3、§6。
