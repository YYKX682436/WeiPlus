# ②-2B-2 热更新空结果缓存验收

基线 `ed4e511f4d122df355e85230f86ed4cd068bd6bb`。目标为 `upgrade_response` 在完整运行时身份相同时的零原始候选查询，不涉及其他定位器、早期 Tinker Hook、DexKit 共享锁、`DexReady` 或资源释放。

## 修复及安全约束

`DexMethodCache` 保留原正向描述符存储；`upgrade_response` 读取时要求描述符列表全部可解析且方法签名有效。新增独立目录的空结果标记，按完整 `DexCacheIdentity` 及 `upgrade_response_v1` 规则版本的摘要区分；不修改原有 `sync_response_consumer`、`manual_updater` 的缓存文件。只有查询正常返回且原始候选数为零、身份完整时写入空标记；异常、非零但不可用、部分不可用或损坏的正向描述符不写空标记，后续保留查询。有效正向结果优先；独立正向屏障使其他进程的旧 FastKV 内存快照不会用空结果压过已发现的正向结果。跨进程文件锁串行化此定位器的决策，进程内锁避免重叠文件锁；存储异常会尝试设置持久保守标记并撤销空标记，不能使用标记的进程继续查询。该文件锁不同于原有 DexKit 共享锁，首次跨进程扫描仍可能等待。

## 基线和回归

修复前 ②-2B-1 同一身份下三次主进程分别查询一次、原始候选均为零，查询墙钟 879.645 / 980.915 / 1163.775 ms。更早的数据及证据边界见 [②-2B-1 报告](HOT_UPDATE_DEXKIT_DIAG_ROUND2_2B_1_2026-11-03.md)。

单元回归覆盖：首次零候选仅查询一次、同身份重建复用、版本/DEX/Tinker 变化失效、异常及非零但不可用重试、部分候选不保存完整快照、损坏、错误类型及空字符串正向描述符重试、正向屏障、存储不可用和锁异常保守回退。五个独立 JVM 在目录尚不存在时并发竞争同一文件锁，仅执行一次空查询，模拟的其他缓存文件保持原样；此测试证明文件锁协调和路径隔离，不等同于 Android FastKV 的完整事务验证。

单独的 Robolectric 集成测试在隔离配置中验证关闭时不安装 Hook；又通过真实 `hookUpgradeResponse` 入口和有效方法描述符验证正向命中安装 Hook、解除后重新安装；另在定位期间撤销 HookRegistry 安装代次，验证旧代次无法安装 Hook。屏蔽热更新设置本身注明重启微信后生效；本轮不改变生产开关，未在真实微信中测试开关关闭/重新启用。HookRegistry 1000 次清理与代次回归、原生库缓存、性能第二轮及阶段 B 回归通过。
